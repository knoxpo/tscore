---
title: Files and bytes
description: "runtime.fs and runtime.bytes, a promise-native filesystem API."
---

Blocking work never runs on the realm thread. `runtime.fs` hands every call to a dedicated 4-thread I/O pool (the libuv model, separate from the CPU pool) and returns a promise.

## runtime.fs

| Call | Returns | Notes |
|---|---|---|
| `readFile(path)` | `Promise<string>` | UTF-8. |
| `writeFile(path, s)` | `Promise<undefined>` | Creates or truncates. |
| `appendFile(path, s)` | `Promise<undefined>` | |
| `readDir(path)` | `Promise<string[]>` | Entry names, sorted. |
| `stat(path)` | `Promise<{ size, isFile, isDir, modifiedMs }>` | |
| `mkdir(path)` | `Promise<undefined>` | Recursive. |
| `remove(path)` | `Promise<undefined>` | File or directory tree. |
| `exists(path)` | `Promise<boolean>` | |
| `readBytes(path)` | `Promise<Bytes>` | Binary read. |
| `writeBytes(path, bytes)` | `Promise<undefined>` | Binary write. |

An I/O error rejects the promise with the OS message, which re-raises at your `await`.

```typescript
await runtime.fs.writeFile("out.txt", "hello\n");
await runtime.fs.appendFile("out.txt", "world\n");
console.log(await runtime.fs.readFile("out.txt"));
const st = await runtime.fs.stat("out.txt");
console.log(st.size, st.isFile);
for (const name of await runtime.fs.readDir(".")) console.log(name);
```

## runtime.bytes

`Bytes` is an immutable byte-buffer handle. It is not an array; you cannot index it. Handles are portable across realms by shared core, like channels.

| Call | Returns |
|---|---|
| `bytes.size(b)` | `number` |
| `bytes.slice(b, from?, to?)` | New `Bytes`; bounds are clamped. |
| `bytes.toString(b)` | `string`, lossy UTF-8 decode. |
| `bytes.fromString(s)` | `Bytes` of the UTF-8 encoding. |

```typescript
const raw = await runtime.fs.readBytes("image.bin");
const head = runtime.bytes.slice(raw, 0, 16);
console.log(runtime.bytes.size(raw), runtime.bytes.size(head));
await runtime.fs.writeBytes("head.bin", head);
```

There is no Node compatibility layer. These are the runtime's own APIs, modelled loosely on Deno.
