## How it works

Every `tscore run` writes a key/value snapshot to `$TMPDIR/tscore-stats-<pid>.txt` every 500 ms and deletes it on exit. `tscore top` scans that directory once a second and redraws the table in place. There is no daemon and no socket.

The live redraw only happens on a terminal. When stdout is piped or redirected (`tscore top | cat`, `tscore top > snapshot.txt`) it prints a single frame with no escape codes and exits.

| Column | Source |
|---|---|
| `UP` | Seconds since the process started. |
| `WRK` | Worker count the pool settled on (0 until the pool starts). |
| `TASKS` / `STEALS` | Chunks executed and chunks stolen from another worker's queue. |
| `HEAP` | Approximate live bytes from the last major GC. |
| `GC m/M` | Minor / major collection counts. |
| `PAUSE` | Last GC pause in microseconds. |
| `ACTORS` | Live actor threads. |

A script whose snapshot is older than 3 s is marked `(stale)`; older than 10 s it is treated as a dead process and its file is removed.

## Opting out

Pass `--no-stats-export` to `tscore run` to skip the snapshot entirely. Benchmarks and the golden tests do this so the writer thread never competes with the measured work.
