---
title: Supported subset
description: "What TypeScript syntax the compiler accepts, and what it rejects."
---

TypeScript Core runs a **defined subset** of TypeScript. The resolver rejects anything outside it with a `not supported in M1` diagnostic that carries a source span. Scope is enforced by code, not by convention. The subset was chosen to be exactly enough for honest CPU benchmarks and real concurrent programs: f64 math, bitwise ops, arrays, objects, closures, async, modules.

## Supported

**Declarations**
`let`, `const`, `function`, arrow functions, `async` functions and arrows. Closures capture lexically, including across `parallel.map` and actor boundaries (by structured clone).

**Values**
`number` (IEEE f64; there is no separate integer type, though the JIT has an integer lane), `boolean`, immutable `string`, `null`, `undefined`, object literals, array literals, functions, promises.

**Operators**
All arithmetic; comparison (`==` and `===` are the same operation on this value set); logical with short-circuit; bitwise (f64 to i32 coercion, `Math.imul` for 32-bit multiply); `typeof`; ternary; compound assignment; `++`/`--`.

**Control flow**
`if`/`else`, `while`, `for`, `for-of` over arrays, `break`, `continue`, `return`, `await` (including top-level).

**Property access**
Dot and computed index. `arr.length`, `arr.push(x)`, `s.charCodeAt(i)`. Out-of-range or non-integer array indexes read as `undefined`, matching JavaScript.

**Strings**
Template literals, concatenation (large concatenations build ropes), comparison.

**Types**
Annotations, `interface`, `type` are parsed and stripped. They are never checked. `: number` on parameters is a JIT hint, see [Type annotations and the JIT](/docs/language/type-annotations-and-jit).

**Modules**
Full ES modules: static `import`/`export`, `export * from`, re-exports, dynamic `import()`, cycles, bare specifiers, top-level await in every module. See [Modules](/docs/language/modules).

**Globals**
`console.log`, `Math.{floor,sqrt,abs,min,max,imul}`, `Date.now`, `performance.now`, `sleep`, `parallel`, `actor`, `Channel`, `task`, `Runtime`, `runtime`. See the [Runtime API](/docs/runtime-api/globals).

## Not supported

| Construct | Notes |
|---|---|
| `class`, prototypes, `this`, `new` | Objects are plain maps. Use closures and object literals for state. |
| `try` / `catch` / `throw` | A runtime error aborts the current task. Rejected promises re-raise at the `await`. Failure isolation comes from actors and scopes, not from unwinding. |
| Generators, iterator protocol, `.then` | Promises are await-only. |
| `Map`, `Set`, `Symbol`, regular expressions | |
| Getters, setters | |
| Destructuring, spread, default parameters | Write the assignments out. |
| `var`, `with`, `eval`, `switch`, `do-while`, `for-in` | |
| Array methods beyond `push`/`length` | No `map`/`filter`/`slice`. Loops are the idiom, and they JIT well. |

<Callout type="warn">
Programs that need any of the above will fail to compile with a span pointing at the construct. There is no partial fallback.
</Callout>

## Error-reporting timing

Since lazy compilation (M6) function bodies are compiled on first call. This changes *when*, not *whether*, subset errors surface:

- **Syntax errors** anywhere in the file: at startup. The whole file is always parsed.
- **Statement-level subset errors** (`class`, `switch`, `try`, `throw`, `do-while`, `for-in`, `import`/`export` in the wrong place) anywhere, plus anything at top level or in parameter patterns: at startup. A cheap scan walks every body.
- **Expression-level violations** inside a lazily compiled body (`in`, `new`, spread, computed keys): when that function is **first called**, with the original span. A body that never runs stays silent.

`TSC_NO_LAZY=1` restores fully eager compilation and startup reporting for everything.

## Documented deviations from JavaScript

- Module cycles are undefined-then-live: reading an import before its module has evaluated yields `undefined` rather than throwing a TDZ error.
- `await` on a settled promise or a plain value does not yield a microtask tick. With no `.then` in the subset the difference is unobservable.
- Runtime errors have no stack unwinding. An error in a `parallel.map` chunk fails the whole map; in an actor handler it fails only that message.
